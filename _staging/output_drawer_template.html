Grammar of Meaning · instrument schema · output-drawer template · S159

Every output drawer, one schema

The engines (Situate · Analyze) already have rigorous drawers. The outputs are free-form — so their schemas, fields, scripts and tests get lost. This template gives every output the same rigor, so there's a fixed place for each output's work — and future reading-SBs know where it goes.

Like the engine drawers (and the library page), an output drawer renders from a registry, never free-form — so it can't drift, and the Resituate update becomes a clean data addition, not fragile const P surgery.

And the drawer links to the OUTPUT, LIVE. The actual rendered artifact (a viz / a reading-room page) is the output's example — it belongs surfaced in the drawer, not buried. Three are already live: Resituation → the sensitivity viz · Comparison → the braid/convergence map · Gloss → the braided reading.

the problem

Rigorous engines, free-form outputs

engine drawers — structured (7 keys)

  • what · why · logic · status
  • example (a real row)
  • fields (data contract, by tier)
  • irr (audit) · code (implementation)

output drawers — free-form, ad-hoc

  • "what it does"
  • "how it runs, step by step"
  • "real result"
  • "how we validated it"
  • "the gloss modes" … every output invented its own

The honest picture: 3 outputs are genuinely produced on the gospels — but all on the Resurrection movement, not the full four gospels (Resituation across levers/rooms · Comparison as the convergence · Gloss as the braided reading). Reception is a narrow end-gap slice. Fan is Mark-16 only; Constellation isn't done on the gospels at all. And crucially — even the produced ones aren't wired into the schema.html output drawers (they live as loose artifacts). That's the gap this template + backfill closes: produced outputs get their "output, live" link; unproduced ones get an honest empty slot — somewhere to put the work, and an honest public record of what's actually done.
