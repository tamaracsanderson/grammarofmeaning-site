## SITUATE — Sitz
**tag:** the world it came out of
**what:** Places the text in its world: the material and historical conditions (its Sitz) that shaped it. Context, not yet meaning.
**why:** The same move can mean different things in different worlds. The Sitz keeps two texts from being read as if they faced the same conditions.
**logic:** IN: raw text + a date → BOX: resolve the date, match against known substrate events (10 categories × 4 Sitz-im-Leben layers), flag where it fell back on model knowledge → OUT: a sitz summary + categories → NEXT: 0.B Paradigm.
**status:** Built · reliability-tested on 2 texts only (Romans 8:28–30, Mark 16) — both biblical; never tested out-of-domain

## SITUATE — Paradigm
**tag:** the story-shapes it thinks with
**what:** Names the interpretive templates the text leans on — the story-shapes a reader already carries and reads it through. A text can invoke several at once, each with its own salience and stance.
**why:** A paradigm is the story-shape a reader already carries and reads the text through &mdash; and it is usually borrowed from whatever the age happens to make available. We explain the brain with the computer because we have computers. In early-modern Europe, when glass was a new and prestigious material, people described their own fragility through it &mdash; the &ldquo;glass delusion&rdquo;, the fear of shattering. The material was to hand, so it became the idiom. That is what 0.B reads: which templates a text is thinking with, how strongly, and whether it stands inside them or argues against them.
**logic:** IN: text + Sitz → BOX: multi-label the templates it references, score salience, mark stance and relation to the dominant one → OUT: a ranked paradigm set → NEXT: 0.C Frame.
**status:** Built · run on 10 sources — 3 gospels, Romans, the prodigal parable, MLK’s Birmingham letter, a 1963 pop lyric, Ali 1964 (3 of them out-of-domain)

## SITUATE — Frame
**tag:** where it stands
**what:** Reads where a text stands &mdash; the angle it comes at its subject from. Two texts can treat the same thing from wholly different positions: one knows it by revelation, another by looking; one is arguing, another consoling. R&#363;m&#299;&rsquo;s telling of the elephant parable puts people in a dark house, each touching a different part and describing a different animal &mdash; the frame is what says which part of the dark you are standing in. It assigns a position on each of the coded axes &mdash; how it claims to know &middot; what it treats as real &middot; what it is finally for &middot; what shape of relation it assumes, and the rest &mdash; each backed by the coder&rsquo;s evidence. A full reading is in the worked example below.
**why:** The frame is the hinge of the whole pipeline &mdash; all four outputs run on it, each using it differently. Engine 2 PERTURBS it (turn one axis, see what world follows). Engine 3 VARIES it &mdash; that is its entire method: a fill is a function from a frame to an answer, so answering the same gap from many frames maps the space of answers the gap admits. Engine 4 takes it as INPUT, coding each attested reception so a later reader&rsquo;s frame can be set beside the source&rsquo;s. Engine 5 HOLDS it as the control &mdash; one frame, several texts, so a difference is attributable to the texts. Which is what lets two texts from unrelated traditions be compared at all.How do we know these are the right eight? The axes are empirically graduated, not asserted. A proposed new axis must clear three gates &mdash; recurrence (does it recur across the corpus?), orthogonality (does it spread independently, or just correlate with an existing axis?), and coherence (one dimension, or several lumped?) &mdash; then a researcher CLC lock. The default is bundle; the bar for a new axis is high. First live test: the single strongest new-axis candidate in the 795 proposals &mdash; eschatological-temporality &mdash; still BUNDLED (it piles onto revelation + telos rather than spreading independently). So the eight are conservative and earned, not a menu we picked. Honest caveat (&sect;2.8): that test is corpus-limited &mdash; 13 of 14 cluster reads are Abrahamic, n=14 &mdash; so the narrow residue (structure-of-historical-time) is deferred for re-test as non-Abrahamic / cyclic-time material grows.
**logic:** IN: text + Sitz + paradigm → BOX: classify onto each axis, loading the allowed values from the vocabulary (fit-or-extend) → OUT: 8 coordinates with confidence → NEXT: Engine 1.
**status:** BUILT + running on atlas_frame_read_placement (the passage-level frame-reader; 12,228 placements across ~911 passage-reads). The relational axis has been restructured from the single frozen ground-world-relation into r_condition (24 values) + r_topology (29 values) — most still candidate under fit-or-extend, which is the true state of a young axis.

## ANALYZE — Grammar
**tag:** the moves it makes
**what:** Produces the unit every later stage is built from. It reads a text and returns two things: an ordered list of moves and a graph of typed edges between them. A move is not a sentence &mdash; it is one operation with its arguments: a teller says someone does something to something, with a result. Those five slots (plus two that classify the move) are the CORE-7. One move decomposed &mdash; and one typed edge &mdash; is in the worked example below.
**why:** Because every later stage takes the move list as its input. 1.B scans each move for what the text leaves unsaid; 1.C ranks the moves against the dependency graph to find the seed; the Fan flips one slot of that crux and works out which other moves cannot survive the flip. Getting the moves wrong is therefore not a local error &mdash; it is the error every stage after this one inherits. That is what turns a text into something you can compare, perturb, or trace.
**logic:** IN: text (chunked at its own native divisions) → BOX: extract each move + its operation, agent and substrate; then type the edges between them → OUT: an ordered move list + an edge graph → NEXT: 1.B Gaps.
**status:** Built and run — 1,957 moves across 32 sources, with all seven CORE-7 slots populated on every move. But the longest text coded so far is 70 moves (the Prodigal Son, Luke 15), and the length-aware front door added later has never been run on a genuinely long text — so behaviour on a whole book is unknown.

## ANALYZE — Gaps
**tag:** what it leaves unsaid — typed and gated
**what:** Finds what the text leaves unsaid but keeps in play &mdash; and types each one. A gap is either a GAP (in-text: the text&rsquo;s own words open a question at the Move layer and don&rsquo;t close it) or a SEAM (between the text and its context or version &mdash; at the Sitz / Paradigm / Frame layers). Each is a typed object &mdash; {layer, locus, subtype, textual_anchor} &mdash; that counts only if it passes five eligibility gates. Subtypes: omission &middot; ambiguity &middot; presupposition &middot; suppression &middot; indeterminacy &middot; incongruity (the last = a held, unresolved contradiction &mdash; two stated things in tension: irony, paradox). The earlier single rule (opaque &times; in-focus) is now folded into two of the gates &mdash; textual_anchor=stated fails, and no activation fails. The layered scan &amp; the five gates are in the worked example below. Honest state: the Move-layer scan is run (8,121 cells); the full four-layer 12-loci scan + the incongruity detector are the v4 upgrade &mdash; specified, build in progress.
**why:** 1.B does one job: it identifies the gaps that Engines 3 and 4 will fill. A gap turns out to be one of three things &mdash; a genuine opening the text cannot close from inside itself, one the text fills itself later, or one another work fills in its reception history. The first is what gets generated into; the second and third are found, not invented. Sorting them is what makes the gaps useful downstream rather than a list of absences.&#9888; Two honest limits, both worth knowing before you trust it. First, routing has never been run on the current instrument: the gaps in the six older texts carry a disposition; the one text scanned on the current slot set carries none. Second, the v4 model widens the scan &mdash; a GAP is in-text (the Move layer, incl. the missing relation between moves, the old &lsquo;edge-gap&rsquo;), and a SEAM is between the text and its context/version (the Sitz / Paradigm / Frame layers). Today&rsquo;s runs are Move-layer only; the SEAM-layer loci + the incongruity subtype are specified and in build. Engine 3 generates against the coded axes for both kinds &mdash; but 1.B currently hands it the Move-layer set.
**logic:** IN: the situated text (Sitz / Paradigm / Frame named) + the move list → BOX: run the layered 12-loci scan (3 loci per layer); tag each candidate {layer, locus, subtype, textual_anchor}; apply the 5 gates and DISCARD failures with the failed gate named → OUT: the typed gaps (GAP in-text + SEAM text-vs-context), residuals flagged → NEXT: 1.C&rsquo;s chair surfaces multiple cuts (high-agreement + high-divergence); the human picks.
**status:** Move-layer scan built + run on the FULL corpus (8,121 cells across 8 sources). The v4 upgrade &mdash; the four-layer 12-loci scan, the 5-gate filter as an explicit stage, the incongruity subtype, and ensemble agreement-count &mdash; is specified (INSTRUMENT_v4_LOCK) and in build; drawer marks those parts coming. &#9888; 6 of 7 older texts were scanned on the earlier nine-position set; only one text is on the locked flat-6, so most of the historical table is on a retired instrument.

## ANALYZE — Seed Ranking
**tag:** which move holds the rest up
**what:** Ranks the coded units to find the seed to act on &mdash; two methods, two seed-types. A move-seed (quantitative) picks the move whose flip reorganizes the most and feeds the Fan; on &ldquo;She Loves You&rdquo; it ranks M4 (the chorus) first. A gap-seed feeds the Gloss &mdash; and here the v4 rule is deliberate: the chair does not pick one &lsquo;best&rsquo; gap. It surfaces several cuts &mdash; the high-agreement, the high-divergence, and the high-consequence gaps &mdash; and the human picks which go to the full crit. Confidence rides an ensemble: run the scan K&ge;3 times, union the gaps, grade each by its agreement-count (5/5, 4/5&hellip;). Each method narrows the field; the researcher makes the call. Both flows &mdash; and the four move-seed measures &mdash; are in the worked example below.
**why:** This is the link from analysis to substitution, and it exists so the seed is not arbitrary. Engine 2 flips one move and watches the world reorganize; if that move were picked at random, nothing downstream would mean much. The ranking narrows the field &mdash; it does not make the choice. That is the v4 correction on the gap side too: no single &lsquo;best-gap&rsquo; rule &mdash; the chair lays out the high-agreement / high-divergence / high-consequence cuts, and the human decides which are worth answering.
**logic:** IN: the move list + the DEPENDS graph (move-seed) &middot; the K&ge;3-pass unioned gap ensemble (gap-seed) → BOX: move-seed = rank moves by ripple (transitive closure of dependents); gap-seed = the chair surfaces multiple cuts (high-agreement + high-divergence + high-consequence), each gap carrying its agreement-count → OUT: a ranked move list + the surfaced gap-cuts → NEXT: the human picks the seed (a move → Engine 2 Fan; a gap → the Gloss).
**status:** Move-seed built, deterministic, no LLM, $0, and writes to a table. All four measures compute (Structural + Ethical deterministic; Thematic + Contingent quantified proxies). The v4 gap-seed rule &mdash; chair-surfaces-multiple-cuts + human-picks, with ensemble-union / agreement-count as the confidence grade &mdash; is specified (INSTRUMENT_v4_LOCK D1/D2) and in build; the drawer shows it as the target model.

## SITUATE — Lineage
**tag:** what it stands on
**what:** Reads the soil a text grew from — the upstream sources it stands on. Where the Frame reads where a text stands, Lineage reads the catena of predecessors it reaches back to: what it quotes, alludes to, echoes, or is structurally built on, and how it re-uses each — faithfully, by extension, or by repurposing. Romans is dense with it: Paul grounds the gospel he preaches in Israel’s own scriptures at nearly every turn.
**why:** The 4th Situate layer (locked S156 CLC v5). Two texts can make the same move while standing on wholly different ground — one improvising, one re-saying an inherited authority. Lineage makes that ground visible, and RESITUATE perturbs it alongside Sitz, Paradigm and Frame (move ONE documented borrowing, see if the reading holds). Its F5 seam — the unsaid in the borrowing — is projected into the one canonical gap store (source_move_gap, locus=‘lineage’) so it flows through the existing rank → chair → gloss pipeline.
**logic:** IN: a coded text + its citing moves → BOX: detect each upstream reference (F1 source-ref), code the borrowing — vehicle (F2), markedness (F3), function (F4) — and the transformation/seam (F5); set fidelity-direction (F6) against the source’s own sense (corpus-coded when the upstream is in our corpus, else model-reconstructed + flagged), source-home (F7), and link-certainty (F8, the ∅-guard: a contested echo is stored-but-gated, phrased interrogatively) → OUT: the lineage records + the F5 seams projected into the gap store → NEXT: RESITUATE.
**status:** Built · ran on Romans (GOSPEL-ROMANS-KJV → 113 lineage records; 55 quotations · 30 allusions · 22 echoes · 5 structural · 1 paraphrase). Validated by IRR226 (5/5). Reliability-tested on 1 text only (Romans) — not yet run out-of-domain; the F6 corpus-coded baseline needs the upstream texts in-corpus, else it falls back to model-reconstruction (flagged, confidence-lowered).
